```markdown
# 나만의 퀴즈 게임

## 프로젝트 개요
터미널에서 실행하는 4지선다형 퀴즈 게임입니다. 퀴즈를 풀고, 새 문제를 추가하고,
목록을 확인하고, 최고 점수를 기록합니다. 프로그램을 종료해도 `state.json`에
데이터가 저장되어 다음 실행 때 이어집니다.

## 퀴즈 주제 선정 이유
주제는 **프로그래밍 / IT 상식**입니다. Python/Git 등 이 과제에서 직접 배운
개념을 퀴즈로 다시 정리해보면 복습 효과가 있을 것 같아 선택했습니다.

## 실행 방법
```bash
python main.py
```
(Windows에서 `python`이 안 되면 `py main.py`, Mac/Linux는 `python3 main.py`)

## 기능 목록
- 퀴즈 풀기: 등록된 문제를 순서대로 출제하고 정답 여부를 알려주며, 다 풀면 점수를 계산합니다.
- 퀴즈 추가: 문제/선택지 4개/정답 번호를 입력받아 새 퀴즈를 등록합니다.
- 퀴즈 목록: 등록된 퀴즈 문제 목록을 확인합니다.
- 점수 확인: 지금까지의 최고 점수를 확인합니다.
- 잘못된 입력(공백/문자/범위 밖/빈 입력)과 Ctrl+C 등에도 안전하게 동작합니다.

## 파일 구조

quiz-game/

## 데이터 파일 설명 (`state.json`)
프로젝트 루트에 UTF-8로 저장되며, 다음 구조를 가집니다.

```json
{
  "quizzes": [
    {
      "question": "Python을 만든 사람은?",
      "choices": ["Guido van Rossum", "Linus Torvalds", "Dennis Ritchie", "James Gosling"],
      "answer": 1,
      "hint": "이 사람의 별명은 'BDFL'이었습니다."
    }
  ],
  "best_score": 83
}
```

- `quizzes`: 등록된 퀴즈 목록. 각 항목은 문제(`question`), 선택지 4개(`choices`),
  정답 번호(`answer`, 1~4), 힌트(`hint`, 선택)로 구성됩니다.
- `best_score`: 지금까지 기록한 최고 점수 (0~100점).
- 파일이 없거나 손상된 경우, 프로그램은 기본 퀴즈 데이터로 자동 복구합니다.
```

## 설계 노트 (Design Notes)
 
### 왜 클래스로 만들었나 (Quiz / QuizGame 분리 이유)
함수만으로도 동작하는 프로그램을 만들 수 있지만, 이 프로젝트는 "퀴즈 데이터"와 "게임 진행 상태"를 여러 기능(퀴즈 풀기/추가/삭제/목록/점수)이 계속 공유하고 갱신해야 합니다. 함수형으로 짜면 이 상태(퀴즈 목록, 최고점수, 점수 기록)를 매번 인자로 넘기고 반환값으로 다시 받아야 해서, 함수가 늘어날수록 상태를 빠뜨리거나 잘못 전달할 위험이 커집니다.
 
클래스를 쓰면 `self`가 상태를 자동으로 나르기 때문에 이 위험이 사라집니다. 두 클래스로 나눈 이유는 책임이 다르기 때문입니다:
- `Quiz`: 문제 하나의 데이터(문제, 선택지, 정답, 힌트)와 그 문제에 대한 동작(출력, 채점, 직렬화)만 담당
- `QuizGame`: 여러 `Quiz`를 모아서 전체 게임 흐름(메뉴, 입력 검증, 파일 저장)을 조정
### 왜 JSON으로 저장했나
표준 라이브러리(`json` 모듈)만으로 바로 쓸 수 있어 외부 의존성이 없고, 텍스트 형식이라 사람이 직접 열어서 값을 확인·수정하기 쉽습니다. 파이썬의 `dict`/`list` 구조와 거의 1:1로 대응돼서 변환 코드(`to_dict`/`from_dict`)가 단순해지는 것도 이유입니다. 데이터 규모가 크지 않은 개인용 프로젝트에는 데이터베이스보다 JSON 파일이 설정/실행 부담이 적어 더 적합하다고 판단했습니다.
 
### 모듈(파일) 책임 분리 기준
| 파일 | 책임 |
|---|---|
| `quiz.py` | 퀴즈 "데이터 모델" — 문제 하나의 표현과 그 자체로 완결되는 동작(채점, 직렬화)만 담당. 파일 입출력이나 사용자 입력을 직접 다루지 않음 |
| `quiz_game.py` | 게임 "오케스트레이션" — 메뉴, 사용자 입력 검증, 여러 `Quiz`를 다루는 흐름 제어, `state.json` 파일 입출력을 전담 |
| `main.py` | 진입점 — `QuizGame` 객체를 만들고 시작시키는 역할만, 로직을 갖지 않음 |
 
기준은 "이 코드가 **파일/입출력을 아는지 모르는지**"입니다. `Quiz`는 자신이 JSON으로 저장된다는 사실조차 몰라도 되고(`to_dict`만 반환), 실제 파일을 열고 닫는 책임은 전부 `QuizGame`에 있습니다. 이렇게 나누면 나중에 저장 방식을 JSON에서 다른 형식으로 바꾸더라도 `Quiz` 클래스는 건드릴 필요가 없습니다.
 
### 커밋 메시지 컨벤션
아래 접두어를 사용해 커밋의 성격을 구분했습니다.
 
| 접두어 | 의미 | 예시 |
|---|---|---|
| `Feat:` | 새 기능 추가 | `Feat: implement play quiz feature` |
| `Fix:` | 버그 수정 | `Fix: match function name in definition and call` |
| `Refactor:` | 동작 변경 없이 구조만 개선 | `Refactor: split into multiple files` |
| `Docs:` | 문서(README 등)만 변경 | `Docs: write README` |
| `chore:` | 프로젝트 설정 등 코드 외 잡업 | `chore: initial project setup` |
 
커밋 단위는 "기능요구사항 1개 = 커밋 1개"를 기본으로 했고, 리팩터링과 기능 추가는 항상 별도 커밋으로 분리해 각 커밋이 무엇을 바꿨는지 하나의 목적만 갖도록 했습니다.
 
### 브랜치 전략
퀴즈 풀기 기능(`play_quiz`)은 `feature/play-quiz` 브랜치에서 작업한 뒤 `main`에 병합(`--no-ff` 방식)했습니다. 기능 하나를 별도 브랜치에서 완성하고 검증한 뒤 `main`에 합치면, 작업 중간 상태가 `main`에 섞이지 않아 언제든 `main`을 안전하게 유지할 수 있습니다. `--no-ff`를 사용해 fast-forward로 병합 이력이 사라지지 않고, "브랜치를 나눠 작업했다"는 기록(merge commit)이 히스토리에 명시적으로 남도록 했습니다.

### 확장성 — 퀴즈가 1,000개 이상으로 늘어난다면
현재 구조는 `self.quizzes`가 파이썬 리스트이고, 조회/출제는 순차 반복(`for`)으로 처리합니다. 문제 수백~수천 개 규모까지는 이 방식으로도 체감 성능 차이가 없지만, 데이터가 훨씬 커지면 다음 한계가 있습니다.
- 실행할 때마다 `state.json` 전체를 메모리에 로드하므로 파일 크기에 비례해 시작 시간이 늘어남
- 특정 문제 검색·필터링(예: 주제별, 난이도별)이 리스트 순회(`O(n)`)로만 가능해 느려짐
이 경우 SQLite 같은 파일 기반 DB로 옮겨 인덱스를 걸거나, 문제를 카테고리별 파일로 분할해 필요한 것만 로드하는 방식으로 전환하는 것이 다음 단계입니다. 지금 규모(문제 수십 개)에서는 오버엔지니어링이라 판단해 적용하지 않았습니다.
 
### 데이터 손상/백업 전략
`load_data()`는 `state.json`이 없거나(`os.path.exists`) 손상된 경우(`JSONDecodeError` 등) 기본 퀴즈로 자동 복구합니다. 다만 현재는 손상 시 **기존 사용자 데이터(추가한 퀴즈, 점수 기록)를 복구할 방법이 없이 기본값으로 대체**되는 한계가 있습니다. 개선 방향으로는 저장(`save_data`) 시마다 `state.json`을 덮어쓰기 전에 `state.json.bak`으로 이전 버전을 남겨두고, 손상 감지 시 `.bak` 파일에서 우선 복구를 시도하는 백업 정책을 다음 버전에서 추가할 수 있습니다.
 
### 기능 변경 시 어디를 고쳐야 하나
| 바꾸고 싶은 것 | 수정할 파일/함수 |
|---|---|
| 점수 계산 방식 | `quiz_game.py` → `QuizGame.play_quiz()`의 `score = round(...)` 부분 |
| 문제 데이터 구조(필드 추가 등) | `quiz.py` → `Quiz.__init__`, `to_dict`, `from_dict` 세 곳을 함께 수정 |
| 기본 제공 문제 내용 | `quiz_game.py` → `QuizGame._default_quizzes()` |
| 저장 파일 형식/위치 | `quiz_game.py` → `load_data`/`save_data`, `DATA_FILE` 상수 |
| 메뉴 항목 추가 | `quiz_game.py` → `show_menu()`, `run()`의 `elif` 분기, 새 메서드 추가 |
